# MarketPulse

Самообучающаяся система анализа новостей и торговли на демо-счёте.
Читает 200+ источников (финансовые СМИ, регуляторы, Reddit, телеграм-каналы),
схлопывает перепечатки в события, оценивает тональность, принимает торговые
решения (long/short) и **дообучается на собственных исходах**.

> Исследовательский проект. Не является инвестиционной рекомендацией.
> Торговля — только виртуальными деньгами на демо-счёте.

## Как это работает

```
219 источников ──> сбор (async) ──> дедупликация (SimHash) ──> события
                                                                  │
котировки (yfinance) ──> признаки: тональность, охват, всплеск ◄──┘
                          обсуждений, экстремумы толпы, волатильность
                                       │
                          модель (онлайн-обучение, SGD)
                          + контрарианский слой
                          + исследовательские сделки (10%)
                                       │
                          риск-менеджер (лимиты позиции/экспозиции)
                                       │
                          демо-счёт ──> исход ──> дообучение ──┐
                                       ▲                       │
                                       └───────────────────────┘
```

Ключевые инженерные решения:
- **Никакого взгляда в будущее**: признаки строятся только по данным,
  доступным на момент решения; для обучения используется время, когда
  система реально увидела новость, а не время публикации.
- **Дедупликация обязательна**: одну новость перепечатывают десятки изданий;
  без схлопывания (SimHash + окно 48ч) модель видит 40 «событий» вместо одного.
- **Издержки зашиты в результат**: 0.1% за круг (комиссия + проскальзывание) —
  большинство наивных сигналов умирает именно здесь.
- **Исследовательские сделки**: 10% решений принимается случайно, иначе модель
  никогда не узнаёт исходов действий, которые сама не выбрала бы.
- **Контрарианский слой**: при экстремуме настроений толпы и неуверенной
  модели — сигнал против толпы.

## Копитрейдинг «умных денег»

Модуль краулит SEC EDGAR (Form 4): инсайдеры обязаны раскрывать сделки
со своими акциями в течение 2 дней. Покупка инсайдера — сильный сигнал long
(покупают только веря в рост), продажа — слабый сигнал short. Сигналы
автоматически копируются на демо-счёт с расширенным горизонтом.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
export PYTHONPATH=src

.venv/bin/python -m marketpulse.cli init      # база + каталог источников
.venv/bin/python -m marketpulse.cli collect   # сбор новостей
.venv/bin/python -m marketpulse.cli nlp       # дедупликация и разметка
.venv/bin/python -m marketpulse.cli prices    # котировки
.venv/bin/python -m marketpulse.cli replay    # разогрев модели на истории
.venv/bin/python -m marketpulse.cli run       # основной цикл (тик 15 мин)

# дашборд-терминал: весь пайплайн управляется кнопками из интерфейса
.venv/bin/uvicorn marketpulse.api.server:app --app-dir src --port 8737
# -> http://localhost:8737 : запуск цикла, каждый шаг пайплайна,
#    тикер-лента, сигналы, сделки инсайдеров, стратегии, живой журнал
```

Демо-счёт брокера (опционально): ключи Alpaca paper в `.env`
(`ALPACA_API_KEY`, `ALPACA_SECRET_KEY`) — ордера будут дублироваться туда.

## Облачный режим (работает 24/7 без компьютера)

Торговый цикл живёт в GitHub Actions (`.github/workflows/marketpulse.yml`):
одна задача крутит тики каждые 15 минут почти 6 часов (лимит раннера),
а в конце **сама запускает следующую** через `workflow_dispatch` —
самоподдерживающаяся цепочка, не зависящая от крона GitHub (который для
новых репозиториев может молчать часами). Крон оставлен запасным
реаниматором. `concurrency` гарантирует одну активную задачу — без дублей
ордеров. Состояние — в облачном Postgres (Neon), веса модели хранятся в
самой базе: раннер не имеет диска между запусками. Локальный дашборд
читает ту же базу: включил ноутбук — вся история на месте.

Ручной запуск цепочки: Actions → marketpulse-tick → Run workflow (step=run).

Настройка: секреты `DATABASE_URL`, `ALPACA_API_KEY`, `ALPACA_SECRET_KEY`
в Settings → Secrets → Actions. Локально тот же `DATABASE_URL` в `.env`.
